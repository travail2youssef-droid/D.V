## 🛒 Parcours de Commande & Cadrage IA Automatisé

### Étape 1 : Formulaire de Commande Immédiate
- Sélection du type de projet : **Site Web** ou **Agent IA / Automatisation**.
- Choix du forfait parmi la grille officielle.
- Définition de l'échéance : *Urgent (< 1 semaine)*, *2 à 3 semaines*, *1 mois*, ou *Flexible*.
- Recueil des coordonnées : **Prénom, Nom, Numéro de téléphone, Adresse email**.
- Résumé clair sans débit immédiat.

### Étape 2 : Entretien de Cadrage Interactif avec l'Agent IA (Nova)
- Redirection instantanée vers l'interface de conversation dédiée.
- **Questionnement progressif et ciblé** :
  - Secteur & cible client
  - Pages & fonctionnalités prioritaires
  - Charte graphique & contenus existants
  - Outils tiers & intégrations souhaitées
- **Intelligence d'arrêt** : L'agent sait s'arrêter après 3 à 4 questions pour ne pas fatiguer le client tout en récoltant l'essentiel.
- **Audit de Compatibilité Automatique** :
  - Évalue si le besoin exprimé s'inscrit dans le forfait choisi.
  - Détecte les fonctionnalités hors périmètre (ex: boutique e-commerce avec paiement Stripe dans une offre Starter) et émet un avertissement d'ajustement constructif.
  - Génère un score de faisabilité (ex: 98/100) et des recommandations techniques claires.
  - Célébration visuelle par confettis et transmission automatique au gestionnaire de commande.

## Mise à jour — site multipage et expérience 3D

### Installation et lancement

```bash
npm ci
npm run build
npm start
```

Pages publiques : `/`, `/expertises`, `/realisations`, `/offres`, `/agence`, `/contact`.
Express sert aussi les liens directs et les rechargements de pages. Le serveur doit donc servir `dist` après le build ; un hébergement statique alternatif doit réécrire les routes vers `index.html`.

En développement : lancer `PORT=3001 npm run server` dans un terminal et `npm run dev` dans un autre. Vite écoute sur 3000 et relaie `/api` vers 3001.

### Mouvement et accessibilité

La scène d’accueil est une géométrie CSS 3D, sans moteur WebGL ni modèle à télécharger. Elle réagit au pointeur et au défilement ; les cartes d’expertise ont un effet de profondeur au survol. Les animations et le parallaxe sont désactivés avec `prefers-reduced-motion`. Navigation mobile, lien d’évitement, focus visible, titres de document et navigation précédent/suivant sont pris en charge.

### Contact réel et administration

`POST /api/contact` valide les données et le consentement, limite les demandes (5 par adresse réseau sur 10 minutes), puis enregistre les contacts dans `data/contacts.json` avant de confirmer la réception. **Aucun email n’est envoyé** : il faut encore intégrer un prestataire email si nécessaire. Les demandes sont consultables en JSON via `/api/contacts`, protégé comme l’administration.

L’administration est fermée par défaut. Configurer `ADMIN_USER` et `ADMIN_PASSWORD` dans l’environnement du serveur puis redémarrer. Ne pas les placer dans des variables `VITE_*` ni les versionner. `/admin` affiche désormais une page de connexion dédiée. La connexion crée une session serveur de 8 heures avec cookie HttpOnly et SameSite=Strict ; la déconnexion révoque la session. Les sessions sont perdues au redémarrage du serveur. HTTP Basic reste accepté pour les clients API existants. Utiliser impérativement HTTPS en production. Les routes de lecture des commandes, modification administrative, configuration IA, registre, contacts et événements SSE sont protégées. Le fichier `.env.example` n’est pas chargé automatiquement.

### Vérifications

```bash
npm run build
npm test
```

Les tests serveur utilisent un dossier temporaire isolé et vérifient validation, persistance, limitation de débit, refus d’accès administratif et chargement direct des six URLs publiques. Ils ne remplacent pas une vérification visuelle dans un navigateur.

### Limites restantes avant production

- Les commandes restent stockées en JSON : migration transactionnelle SQLite/PostgreSQL encore nécessaire pour éviter les écrasements concurrents pendant les appels IA.
- L’administration possède une connexion par session et une déconnexion. Elle utilise un seul compte configuré par environnement : comptes multiples, rôles, récupération de mot de passe et MFA restent à développer. Les sessions en mémoire nécessiteraient un stockage partagé en déploiement multi-instance.
- Les nouvelles commandes possèdent un UUID et un jeton client privé requis pour le chat et la finalisation. Les anciennes commandes sans jeton ne peuvent plus utiliser ces routes ; elles restent consultables par l’administration. Une reprise sécurisée par email reste à développer.
- Valider strictement les endpoints IA/webhook et bloquer les réseaux privés pour durcir la protection SSRF.
- L’audit est une préqualification heuristique, pas une garantie de faisabilité.
- Les données historiques de démonstration déjà présentes dans le dépôt doivent être remplacées par un stockage privé avant utilisation réelle.


## Administration repensée et logo officiel

Le logo fourni est recadré depuis l’image d’origine, sans régénération : `public/assets/digitalverse-logo.png` et `digitalverse-emblem.png`. Il est partagé par l’ensemble du site.

L’espace `/admin` est maintenant une page autonome responsive :
- Connexion avec identifiant et mot de passe, erreurs explicites et limitation des tentatives.
- Bouton **Explorer la démonstration**, sans authentification : uniquement des fixtures fictives et aucune écriture ni requête aux API privées.
- Vue d’ensemble : compteurs calculés depuis les données, commandes récentes et répartition par étape.
- Commandes : recherche, filtre de statut, fiche latérale, notes internes, changement de statut, conversation et préqualification.
- Contacts : lecture des demandes et réponse via le logiciel email local. Le site n’envoie toujours pas d’email automatiquement.
- Livrables : liens http/https et accès à la gestion existante.
- IA & intégrations : accès aux réglages avancés existants, sans supposer que les fournisseurs sont connectés.

Le rafraîchissement du nouvel espace est manuel. Les anciens outils avancés conservent leur propre mécanisme temps réel lorsqu’ils sont ouverts. Les tests couvrent aussi la connexion, les attributs de cookie, l’accès privé et la révocation de session à la déconnexion.
